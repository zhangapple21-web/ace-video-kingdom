# ACE「桌子」视角 v1

这份抽象来自网易文章《给具身智能，搭一张足够大的桌子》。它不是新增平台或调度器，而是用来判断一个协作场是否真的在把事做完。

## 四个最小功能

1. **需求卡**：谁有真实问题，验收结果是什么，哪些信息可以公开。
2. **能力卡**：谁能提供什么能力，当前证据到哪一步，不能把自述当验证。
3. **验真卡**：用一个边界清晰的小任务比较完成率、稳定性、失败原因、成本和返工，不以宣称替代结果。
4. **跟进卡**：匹配后记录是否接通、是否完成、为什么中断；撮合成功不等于业务成功。

## 在 ACE 与自由区的用法

- **自由区**：可以把模型、问题、失败样本和奇怪想法放到同一张开放桌上，允许探索和分叉；每个参与者可选择发言或不发言，不强制排队。
- **ACE 研究层**：只吸收经过验真的能力、明确的失败和可复用的修订规则；桌上的热闹不自动变成生产候选。
- **短剧编剧室**：需求卡是本集要解决的戏剧问题，能力卡是主笔/反方/导演等职责，验真卡是单镜头动作验收，跟进卡是镜头通过、返工或供应商失败。

## 边界

- “桌子”是观察和证据组织方式，不是第二套 Scheduler、Router 或 Runtime。
- 需求、测试数据、企业/个人身份默认不公开；传播必须有授权和事实完整性。
- 不承诺订单、融资、成片或模型效果；只记录匹配、验证和结果。
- 谁能设定议题、准入、证据可见范围和结算方式，谁就在叙事上拥有“席”；不能只凭参与者身份推断其拥有规则控制权。

## 当前最小落地

先在已有 manifest、director review 和研究复盘里补四个字段：`need`、`capability_evidence`、`verification_result`、`follow_up`。不新建服务，不新建常驻队列。
