# 视频王国 vs. AI 短剧制作完整工作流

更新时间：2026-09-13

对比对象：

- 本项目：`docs/VIDEO_PRODUCTION_WORKFLOW_PLAYBOOK.v1.md`、`docs/ASSET_WORKFLOW_ARCHITECTURE.v1.md`、`governance/production_workflow_profile.v1.json`
- 外部参考：`C:\Users\Administrator\Desktop\AI 短剧制作完整工作流.md.txt`

## 结论

两者不是竞争关系，而是上下层互补：

- 视频王国负责“能不能安全、可追溯、可恢复地生成和交付”。
- 外部工作流负责“做什么内容、如何编排创作、怎样围绕观众节奏复盘”。
- 生产主链继续使用 `Video → agnes-video-2.5-flash` 和 `imagegen → gpt-image-2`；外部文档不改变 Provider。

## 逐阶段比较

| 环节 | 外部工作流优势 | 视频王国优势 | 决策 |
| --- | --- | --- | --- |
| 立项定位 | 目标平台、受众、集数、预算、风格的创作者视角清晰 | 有授权来源、故事根、状态和证据边界 | 吸收立项卡字段，接到 STORY_ROOT 前置 |
| 剧本创作 | 角色动机、分集梗概、3 秒钩子等内容方法实用 | 强调因果、信息点、情绪变化和结局回收 | 吸收节奏提示，不把“3 秒/30 秒”当硬保证 |
| 分镜 | 给出易懂的镜头表和 JSON 示例 | `initial_state → single_action → end_state`、机位/轴线/声音硬门 | 以视频王国 Shot Core 为准，吸收字段表达 |
| 视觉资产 | 角色定妆、多视图、场景图库理念直观 | `asset_id`、用途、SHA-256、权利、连续性桥和 fail-closed | 资产治理以视频王国为准 |
| 视频生成 | 提倡图生视频、首尾帧和多版本备选 | 固定 Agnes 2.5 Flash、admission receipt、幂等、轮询、失败恢复 | 外部方法进入提示词/分镜层，不进入 Provider 层 |
| 配音配乐 | 角色固定音色、按情绪选 BGM、对白清洗 | 音频前置约束、`AUDIO_PENDING` 门、字幕/混音本地管线 | 两者合并；云端 ASR/TTS 仍保持可替换 |
| 剪辑合成 | 卡点、转场、调色、字幕观看体验建议具体 | selected-only assembly、媒体哈希、字幕/音频/全片 QC | 外部提供审美检查项，视频王国控制交付门 |
| 审核发布 | 平台合规、封面标题、数据复盘闭环 | 来源/权利、合规、交付证据和 `delivery_approved` 门 | 增加发布复盘层，但不放松交付门 |

## 哪个更好

- 如果目标是“创作者快速规划一集短剧”：外部工作流更轻、更容易执行。
- 如果目标是“后端系统批量生成、失败可恢复、结果可审计”：视频王国明显更强。
- 如果目标是“持续生产并根据完播率迭代”：两者结合最好；外部文档补内容策略，视频王国保证工程可靠性。

## 已吸收与暂不吸收

已吸收：

1. 立项卡和八阶段编排作为项目级导航。
2. 3 秒钩子、结尾悬念、角色固定音色、先小样后全量作为创作检查项。
3. 分镜 JSON 的人类可读字段，映射到现有 Shot Core，不创建第二种运行时合同。
4. 发布后的完播率/弃剧点作为下一轮 STORY_ROOT 的输入，暂存为复盘字段。

暂不吸收：

1. 外部文档中的模型/平台选型表，不自动切换 Agnes 或 Imagegen。
2. “一集 15–30 镜头”“3 秒/30 秒”等经验范围，不写成 Provider 能力承诺。
3. 外部服务账号、上传逻辑和第三方调度器，不绕过本项目准入、收据和密钥边界。

## 以后怎么用

做视频前先查：

1. 本登记册 `REFERENCE_MINES.md`，确认是否已有可复用资产或方法。
2. 本对比文档，判断需求属于创作层还是控制层。
3. 现有 episode/shot contract、资产索引和收据，再决定是否执行。

这样“抽屉”里的参考会持续进化，但不会把第二套工作流偷偷变成第二个生产系统。
