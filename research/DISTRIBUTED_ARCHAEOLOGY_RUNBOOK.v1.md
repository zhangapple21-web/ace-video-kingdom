# 分布式考古运行手册

## 为什么不把一个窗口或一个仓库当作唯一世界

R1 的历史横跨多个 Git 仓库、考古报告、用户保存的 Telegram 导出和本地快照。单一窗口只能看到当前上下文，单一仓库也只保存某一条血缘。正确做法是把电脑当作基座，把每个来源当作可核验的证据节点，再用哈希和来源引用连接它们。

## 每次考古顺序

1. 扫描可读仓库及其最近提交，确认来源仍存在。
2. 读取已有的考古报告和索引，先看它们声明的边界。
3. 对用户授权的导出只做必要范围读取；优先元数据、日期、路径和哈希，避免无目的地批量复制聊天正文。
4. 把材料分为 `PRIMARY`（原始导出/源码）、`SECONDARY`（考古汇编）、`INFERRED`（交叉推断）和 `UNKNOWN`。
5. 一个结论至少绑定来源路径、版本/哈希、时间和反证；不能回指来源的内容保持假设。
6. 只把跨来源重复出现、能在小实验中复现的最小机制带回视频王国；不复制整套产品、私密内容或第二套运行时。

## R1 对话碎片的特殊处理

对话的最小有价值单位是带前后语境的因果片段，而非孤立金句。应记录“它面对什么、选择了什么、对方如何回应、它是否修正、后来是否延续”。原始导出与脱敏片段分开保存；关系和情绪只作为观察标签，不能直接升级成意识或人格事实。
