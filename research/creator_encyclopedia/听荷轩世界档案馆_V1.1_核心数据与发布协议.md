# 听荷轩世界档案馆 V1.1

## 定位

听荷轩不是“带百科页面的小说网站”，而是**以世界实体、关系和演化历史为核心，以小说和剧集为公开表达层的世界档案系统**。

Quartz v5 只作为 Markdown 内容渲染、全文检索、内部链接、反向链接和图谱导航的参考层。它不是听荷轩的世界数据库，也不是唯一真相源。

## 四个平面

### 1. 世界真相层（Canonical）

人物、事件、关系、地点、物件、规则、版本和证据。对象拥有稳定 ID；内容修改产生 revision，不静默覆盖历史。

### 2. 创作演化层（Authoring）

推演、候选分支、草稿、冲突、审阅和发布候选。CREATOR_LIVE 可以产生候选，但不能自动把候选变成公开事实。

### 3. 公开呈现层（Public）

小说正文、人物百科、家族/关系谱、事件时间线、公开资产。只读取已发布快照，不读取工作区和内部收据。

### 4. 生产溯源层（Production）

剧本版本、角色包、场景、镜头、音频、视频和验收记录。它只能引用 Approved State，不反向改写世界真相。

## 对象协议

### 稳定身份与修订

```text
PER-001（稳定身份）
  ├── revision r001（初始）
  ├── revision r002（补充）
  └── revision r003（发布）
```

改名、身份揭示、合并、拆分必须保留 `supersedes` / `alias_of` / `split_from` 等血缘，不能把每次修改伪装成全新人物。

### 关系是独立对象

```json
{
  "id": "REL-001",
  "from": "PER-001",
  "to": "PER-002",
  "type": "guard|family|contract|rivalry|unknown",
  "status": "developing|confirmed|disputed|ended",
  "valid_from": "EVT-001",
  "valid_to": null,
  "evidence": ["SC-007"],
  "visibility": "public|internal",
  "revision": "r001"
}
```

谱系图只画关系对象，不从 Markdown 链接猜亲属关系。

### 事实状态分离

每条事实至少保留：

- `canon_status`：是否进入当前正式世界
- `publication_status`：读者是否可见
- `epistemic_status`：已知、传闻、误解、未知
- `revision_status`：草稿、审核中、批准、撤回
- `branch_id`：所属分支
- `effective_time`：世界内生效时间
- `evidence`：证据链

“角色不知道”不等于“作者未确认”；“角色声称”也不等于世界事实。

### 三套时间

- `world_time`：故事世界实际发生时间
- `narrative_order`：读者在第几场/章看到
- `revision_time`：创作者何时创建、修订或发布

缺失时间保持 `UNKNOWN`、区间或相对时间，不强填日期。

### 证据链

```json
{
  "id": "EVID-001",
  "source_type": "chapter|scene|event|asset|revision|author_note",
  "source_id": "SC-007",
  "claim_id": "CLAIM-001",
  "status": "confirmed|inferred|disputed|unknown",
  "visibility": "public|internal"
}
```

AI 推断只能标为 `inferred`，不得静默升级为作者确认。

## 发布边界

```text
内部工作区
  → 结构/连续性检查
  → 发布候选快照
  → 人工确认
  → public snapshot
  → 网站只读取 snapshot
```

当前 CREATOR_LIVE 仅生成本地只读导出，`production_integration=false`，未部署域名。

## 数据职责（Cloudflare 以后再接）

- Cloudflare Pages：公开静态阅读层
- Workers / Pages Functions：鉴权、查询、发布动作和上传签名
- D1：实体、关系、事件、版本、证据和审核记录
- R2：图片、视频、原始文件和媒体对象
- KV：缓存、配置和短期派生数据，不承担完整世界数据库
- Git / 导出快照：可审阅、可恢复的版本资产

第一阶段不同时建立两套互相竞争的主库。先以本地版本化导出验证对象协议，再决定 Git/D1 的主从关系。

## Quartz 吸收边界

### 吸收

- Markdown 内容发布
- 内部链接、反向链接、全文搜索
- Explorer、Graph、Canvas 作为导航参考
- 自定义页面类型与主题布局

### 不直接照搬

- 不把 Markdown 文件当作关系数据库
- 不用页面链接推断家族关系
- 不让 Quartz 直接读取 CREATOR_LIVE 工作区
- 不把 Quartz 默认主题当作听荷轩视觉风格

## 听荷轩自己的视觉方向

- 纸本档案感：暖白、墨黑、旧纸灰
- 荷叶青/黛青作为主强调色，朱砂/琥珀只用于状态和证据标记
- 首页采用“六区档案入口”：听荷轩首页、人物百科、谱系图与关系网、事件档案与时间线、世界设定与视觉资产、剧集与创作溯源
- 关系谱使用卡片和证据抽屉；节点点击先看关系状态和来源，再进入详情
- 保留“示意图/读者入口/角色资产/世界连接/果因追踪”等人话标签，不做纯技术后台感
- 公开阅读与创作者档案视觉同源，但数据权限、状态颜色和内容范围严格分离

## MVP-01 验收

1. 人物、事件、关系、章节、地点、物件六类对象有稳定 ID。
2. 每个公开对象能回到章节/场次/事件证据。
3. 人物关系和家族关系可以展示，但不把未知关系画成事实。
4. 内部推演与公开快照物理分离。
5. 本地导出可重建，源文件变更可检测。
6. 未接入 Agnes、Beat、Shot、生产入口。
