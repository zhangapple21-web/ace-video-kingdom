# 龙门短视频质量根因收口（2026-09-05）

## 结论

本次“国外坟墓/英文地图 + 5 秒两张图拼接”主要是制作链路的控制面断裂，不是单纯模型突然变差，也没有证据表明 Scriptify/Novel2Script 已经接管了实际渲染器。

## 可复核事实

1. 用户截图对应的旧样片是 `media_staging/longmen_s01a_camera_wide_r1/S01A_CAMERA_WIDE_R1.mp4`，任务记录为 `agnes-video-v2.0`。逐帧可见墓牌出现 `L...Fa...` 等伪英文/乱码字样；源场景锚图本身没有这段文字。
2. 旧 v2.0 路径的素材/镜头控制没有形成供应商可验证的锁定合同，机器节奏通过不能证明内容连续或语义正确。
3. Longmen T03/T04 返工改走 `agnes-video-2.5-flash` keyframe；同一场景图被同时作为首帧和尾帧，且 `movement=NONE`。该组合此前没有控制面证据，模型仍自行生成坟牌特写、花束和构图漂移。
4. T04 还出现 704x1280，而合同要求 720x1280；Provider SUCCESS 与导演可交付不是同一个状态。
5. 文姬的可观看样片使用的是 2.5 Flash reference 模式，并且每镜只绑定批准的场景锚图；这与 Longmen 旧 v2.0/中间 keyframe 路径不同。
6. 当前修复试投 `S01A_T03` 使用 reference 模式、只发送 `SC01` 场景锚图，媒体为 720x1280、6.592 秒、无内部切换、连续性扫描无突跳；逐帧接触表没有英文、地图标记、花束或坟牌文字。但画面仍偏近，暂不标记为最终交付。

## 已落地的门禁/修复

- 同一首尾图 + `keyframe` + `movement=NONE` 直接阻断，防止把两张静态图伪装成连续镜头。
- 内部 `provider_asset_ids` 只用于筛选素材，不再错误地发给供应商。
- Agnes 2.5/2.5 Flash 不支持的顶层 `negative_prompt` 不再发送；负面约束仍写入结构化 prompt。真实接口已用两次拒绝响应验证了这两个字段兼容性问题。
- Longmen S01A 新合同只给供应商一张批准场景锚图，并显式禁用英文、地图标记、墓碑文字、花束、近景切换、推拉摇移和新增事件。

## 尚未闭合

- 当前 reference 试投虽然连续，但构图仍偏近；需要换用真正的宽景批准锚图或在生成前做可验证的构图控制，不应靠后期裁切假装宽景。
- 还没有完成 S01A 后续镜头的逐镜生产；在首镜创意门通过前不得继续批量生成 S02A-S06A。
- Scriptify/Novel2Script 的现有仓库更像解析/模板与研究参考，尚无证据证明其已接管本地实际渲染入口。
