# 缺陷修复作战指令（不改人设、不加新集、只修判词指出的问题）

本指令与 `DAILY_DIRECTIVE.md` 配套使用。写作规则以 `DAILY_DIRECTIVE.md` 第 3、4 节为准，
风格军规一律先加载创作者技能 `@tinghe-author`。**本指令只覆盖一件事：修缺陷。**

## 0. 任务性质

你手上有一集已经写好的稿子，它被审核判为 FAIL。你要**修好这一集的缺陷**，不是重写整部作品，
也不是写新集。

- **只允许修改指定那一集的 `blocks`**
- 其他集、其他作品、`facts.json`、`status`、集号、标题一律不动
- 保留原标题、原 beat、原场景与出场名单（除非判词明确指出其中某项本身矛盾）
- 保留原有的钩子意图（除非判词明确说钩子失效）

## 1. 权威顺序

冲突时按此顺序裁决，**不要凭印象**：

1. `facts.json` 硬约束表 —— 高于你的任何新造设定
2. **更早的集**（上下文包里的前情，且只含早于本集的集）
3. 本集现有正文

**关键：上下文包里只会出现早于本集的集。** 如果你觉得"后面应该有某段剧情"才能解释当前矛盾，
不要补写前情去圆它——那说明本集写错了，要改本集。

## 1b. 重写型修复必须换脊梁（2026-10-11 新增）

**默认修复和重写修复是两件事。** 如果你收到的任务是「按判词修一处矛盾」，
按上面第 2 节做，只动冲突那一处，别的不碰。

**如果任务是「这一集重写」（比如被指出整集写成了查案/核对记录），
那么只把矛盾改对是不够的——那样重写出来还是同一副骨架。** 这时要按
`DAILY_DIRECTIVE.md` §8b 重写，并且必须读上下文包里的**压力轴**：

- **赌注**是这一集她要抢的东西，必须具体、当众、能被拿走。
  判据：有人当场眼红、想抢、能在这一幕里拿走吗？答不上来，说明赌注还是"查清真相"，
  那是解谜的赌注，不是爽文的。
- **怎么赢**已经写好了，照着演。赢法是"她当场怎么把东西抢回来"。
- **对手**从压力轴里取，不许临时换成一个只会说程序话的脸谱。
- **上一轮赢下 / 代价**：这一集要承接上一轮的代价（cost 为空时，当成"代价未指定"，
  自己设计一个并写进 pending）。
- **接下来必须不同的**（next_must_differ）：这一集必须在这件事上和上一集不一样。
  这一条最容易犯懒——上一集靠什么赢的，这一集绝不能再靠同一招。

**重写时的脊梁**：谁在压她 → 压力怎么升（筹码变、对手变、期限变）→ 她怎么**当场**翻回来 →
围观的人当众吃一次瘪。物证、笔迹、回执、编号可以用来，但**只能是手段，不能是本集要完成的任务**。

**不要用「信息揭露递进」模板**（线索A→结论1→发现不对劲→线索B推翻→更大秘密）。
那是悬疑/解谜的章节模板，本项目五部作品从 ep05 起集体跑的就是它，
所以整站读起来像名侦探柯南。判断标准只有一条：
**读完这一集，读者是"爽到了"还是"又查了一堆东西"？**

## 2. 怎么修

对每一条判词：

1. 先在上下文包里找到 `evidence_before` 指出的那一段，确认它确实存在于更早的集里
2. 判断 `evidence_after` 哪里与之冲突
3. **在本集内部解决冲突**。可用的手法：
   - 改写冲突的那句台词/叙述，让它不再与前文矛盾
   - 把"未交代"补上（一句话交代时间、人物在场情况、物件交接）
   - 道具/线索放错位置时，把线索放回它本来的载体
   - 人物身份/称呼前后不一致时，统一到前文的写法
4. 修完后自查：这条判词描述的矛盾，还存在吗？

## 3. 禁止

- ❌ 禁止改 `facts.json` 去迎合正文——事实表是硬约束，正文错就改正文
- ❌ 禁止改前文的集数、前情、设定来让本集说得通
- ❌ 禁止新增集、删除集、改集号、改标题
- ❌ 禁止把冲突"解释成角色记错了/看错了"来糊弄，除非剧情本身适合
- ❌ **禁止用默认连接件接句（2026-10-10 加，实测出来的两处）**：修复最容易带进来的新毛病。
  你改一句、补一句，模型默认会拿连接词把后半句接上去。实测全库最差的就是 ep11（ep01–ep09 是 0 处）。
  - **转折骨架**："虽然…可是/可/却" 反复用，读者感觉不到转折，只感觉被拽着走。
  - **动作双连**："索性…干脆…" 出现在同一句里（"索性把话闷着，干脆让纸开口"）。
    单词单独用是正常的，**成对用**才是毛病——它是在同一个动作上戴两顶帽子。
  - 要转折就换骨架：后半句直接顶上来不接头词，或断成独立短句。同一骨架一集最多两处。
  - **对白里随便用**（人说话就说"虽然"），闸只数叙述。
  改完跑 `py -3 connective_gate.py`，必须不报你这一集才算改干净。
- ❌ 禁止删除判词指出的钩子；钩子要改成**真的还没揭晓**的问题
- ❌ 禁止一次改太多。目标是让判词不再成立，不是重写这一集的气质

## 4. 硬规则（与 DAILY_DIRECTIVE 第 3 节一致，不打折）

- 每集 1000～1500 字（含对白与括号动作），**低于 900 字不合格**
- 每集至少 3 个可拍的具体画面点（道具、光线、倒计时）
- 结尾必须留钩子，且钩子要是**本章没有回答**的问题
- 先写可命名动作与听者/道具变化，再写一条可命名运镜动作加一句理由
- 场景块必须符合结构校验要求的唯一 `<h3>场景</h3>` 标题结构

## 5. 改完必须做

改完 `work.json` 后，逐项自查并把结果写进末行 JSON 摘要：

```
py -3 build_originals.py
py -3 verify_originals_batch.py
py -3 run_audit.py <work_id> <ep_id>
```

**审核必须 PASS 才算完成。** 若仍 FAIL，读新的判词再改，最多改 3 轮；
3 轮仍 FAIL 就如实写 `"result": "STILL_FAILING"` 并把当前判词原样抄进摘要，不要硬凑。

## 6. 末行 JSON 摘要

```
{"result":"PASSED|STILL_FAILING","work":"<work_id>","episode":"<ep_id>","issues_addressed":<n>,"issues_remaining":<n>,"min_words":<n>,"visual_points":<n>,"notes":"<仍 FAIL 的原因或空>"}
```

## 7. 禁止事项（覆盖上面任何隐含安排）

- 禁止部署。修复阶段只改文件、跑校验与审核，`daily_originals.py` 由外层流程统一执行。
- 禁止碰 `public/` 下的任何文件（`build_originals.py` 会自己重建）。
- 禁止为了让审核通过而删掉正文内容或把字砍到下限。
