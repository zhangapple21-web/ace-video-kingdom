# ACE 连续性保持认知内核 v1

## 定义

ACE（Autonomous Civilization Engine）在本系统中不是视频应用，也不是某个模型、进程、技能或插件。ACE 是负责保持身份、记忆、证据、边界、判断和恢复能力的连续性认知层；“认知芯片”是架构比喻，表示这层能力在执行资源更换后仍可重建。

视频王国只是 ACE 的一个能力域。自由区、研究、资产治理、模型路由、运维和其他未来应用都必须共享同一套连续性契约，但不能互相污染项目状态。

## 永久锚点与临时居民

只有以下可验证资产属于连续性锚点：

- 版本化的身份、L0 硬约束和分层记忆；
- 事件、决策、任务和媒体收据链；
- 能力证据、失败复盘和经过门槛晋升的经验；
- 项目身份、状态快照、哈希和可恢复的交接记录；
- Git 版本与远程同步证据。

以下对象都是临时居民/执行劳动力，不得成为系统身份或唯一真相源：

- 进程、窗口、会话、守护进程和工作线程；
- 模型、Provider、API 网关和密钥；
- Skill、Plugin、脚本、CLI 和外部仓库；
- 某次成功调用、某个缓存、某台机器或某个工作目录。

临时居民可以被发现、探针验证、启用、降级或退休，但替换它们不能丢失连续性锚点。

## 连续性不变量

1. 每次运行都绑定 `project_id`、`run_id`、记忆上下文哈希和证据引用。
2. Provider 只能产生候选结果，不能写入身份、L0 约束、经验基线或交付批准。
3. 进程退出、模型下线、技能缺失或插件替换后，系统必须能从收据和版本化记忆恢复，而不是依赖进程内状态。
4. 能力增长必须经过 `baseline → change → test → evaluation → compare → promote/rollback`；代码变多不等于能力增长。
5. 新领域先复用 ACE 连续性层，再注册自己的能力和项目状态；视频入口不得被误当成 ACE 唯一身份。

## 居民生命周期

`DISCOVERED → PROBED → ACTIVE → DEGRADED → RETIRED`

状态变化只影响执行选择，不改变 ACE 身份。`ACTIVE` 不是永久驻留许可；没有近期证据的居民必须重新探针，失败时按同能力降级或阻断。

## 结果学习闭环

每次真实执行都要记录修改前后的指标、失败原因、采取动作、结果和可复用条件。只有可重复、无回归且有明确收益的经验才能晋升到长期能力账本；否则保留为拒绝或待复盘证据。

## 入口规则

应用可以有自己的入口（例如视频王国的 `tools/video_kingdom_entry.py`），但入口只是能力域适配器。任何跨域自动升级、恢复、学习和治理都必须回到 ACE 连续性资产，不能把某个应用入口、模型或技能包装成 ACE 本体。
