# 全视频项目生产流程手册 v1

## 目的与边界

这是一份跨项目可复用的生产流程，不是某一镜头、某一模型或某个平台的操作教程。目标是把“灵感、试错、素材、生成、剪辑、交付”拆成可检查的状态，减少重复生成、连续性漂移、音画错配和把候选品误报成成片。

自由区允许失败，现实层只接收通过门禁的资产包和成片。任何外部文章只能提供工作流机制参考，不能证明当前 Provider 的接口、价格、时长、稳定性、版权或商业授权。

## 总原则

1. 先定义，再生成：脚本、视觉圣经、角色/场景/道具资产包和分镜合同先于视频调用。
2. 图像锁外观，运动提示写变化：不要让运动提示重新发明角色、场景和道具。
3. 一个镜头一个主要动作或对白节拍；复杂动作拆成准备、峰值/冲击、恢复三个边界。
4. 资产声明不等于 Provider 已收到；Provider 完成不等于导演通过。
5. 失败保留证据，子分支保留父分支；不靠盲目重试覆盖失败。
6. 只有哈希绑定、可重建、连续性通过的结果，才允许从 `BLOCKED` 变成 `READY`。

## 端到端流程

```text
IDEA / 授权来源
    ↓
STORY_ROOT：故事因果、信息点、情绪变化、结局回收
    ↓
VISUAL_BIBLE：风格块、色彩、光线、画幅、角色和空间不变量
    ↓
ASSET_LIBRARY：角色包、场景包、道具包、连续性桥接、SHA-256
    ↓
STORYBOARD：镜头功能、初态→单动作→末态、机位、声音、时长
    ↓
DIRECTOR_PREFLIGHT：提示词锁、首帧空间、摄影机路径、光线动机、尾帧桥
    ↓
ASSET_GATE：缺项/哈希/用途/连续性任一失败 = BLOCKED
    ↓
GENERATE：先选首帧，再做受控图生视频；每次请求有 receipt
    ↓
SHOT_QC：媒体完整性 + 多帧连续性 + 表演/动作 + 音频 + 导演复核
    ↓
ASSEMBLY：仅装配 selected takes，统一颜色、字幕、声音和节奏
    ↓
EPISODE_QC：全片连续性、音画、来源、合规、导出完整性
    ↓
READBACK：分辨率、帧数、音轨、字幕轨、时长与人工听感状态
    ↓
DELIVERABLE / RESEARCH_CANDIDATE
```

## 阶段 0：故事和镜头设计

先写脚本，再拆镜头。每个镜头必须能回答：

- 这一镜在故事中做什么，观众新增知道什么；
- 角色状态和情绪发生什么变化；
- 初态是什么、唯一主要动作是什么、末态是什么；
- 机位、轴线、景别、视线和时长是什么；
- 对白、环境声、音效和转场是否有明确节拍。

长片段不要用一个提示词硬塞进多个动作。需要转身、拿取、抬头、镜头移动等连续行为时，拆成多个镜头或明确的动作边界。

## 阶段 1：视觉圣经和资产库

### 视觉圣经

在生成场景前锁定一个可复用的 style block：风格、光线、色彩、材质、画幅、镜头观感。后续提示词只允许在镜头所需处追加变化，不要每镜重新发明风格。

### 角色包

至少记录身份锚点、正面/侧面/背面或三视图、服装前后、发型、表情范围、手型/关键动作能力、身高比例和禁止变化项。多人同框或复杂服装时，资产包必须升级，不可仅凭文字假定位置和比例。

### 场景包

至少记录建立镜头、主视角、反打/侧后方、空间纵深、光源方向、天气/时间和关键可移动元素。场景拼图或海报只能当参考板，不能自动当作可开工资产。

### 道具包与连续性桥

锁定物件的数量、形状、颜色、尺寸、持握/摆放位置和可见状态。相邻镜头必须有 `previous_end_state → next_initial_state` 的证据；不能用“看起来差不多”代替桥接。

### 资产状态

资产包至少要有：`asset_id`、用途、来源路径、`sha256`、引用关系、权利/来源说明、缺项列表、校验时间和收据。资产存在但哈希不能重建、用途不明或连续性未证明，状态仍为 `BLOCKED`。

## 导演预检与连续性桥

提示词提交前必须通过 `tools/validate_shot_prompt.py`：风格锁、主体锁、场景锁、数量约束和负面约束缺失，或非 UI 模式出现禁用界面词，均阻断。导演预检使用 `tools/validate_director_manifest.py --strict` 检查首帧空间、主体路径、摄影机路径、光线动机、曝光和白平衡。相邻镜头的摄影机状态、光线状态和尾帧必须通过 `tools/validate_continuity_bridge.py`；`READY` 桥接还必须有实际帧证据。生产适配器在向 Agnes 提交请求前会自动执行上述三项门禁，调用者无需再次提醒；`legacy`/`research` 仅用于不可交付的兼容或探针任务。

每个有表演的镜头还必须写清五个动作问题：说话时手和身体在做什么、听者表情如何变化、何时停顿、独白时嘴部是什么状态，以及为什么在此切镜才有电影感。字段位于 `director_preflight.performance`；无对白或无听者时必须明确填写“不适用”，不能留空或靠模型临场猜测。

正式开拍还必须附带 OneAPI 角色房间收据 `role_audit`：至少使用 `standard` 席位（主笔、分镜、反例审计、连续性编辑、导演收敛），复杂项目使用 `full_audit`。每个必需席位必须为 `COMPLETED`，反例审计评价必须为 `PASS`，且收据必须声明 `production_submission=NOT_PERFORMED`。`rapid` 只能用于整理和探针，不能作为正式开拍的审计凭证。

## 阶段 2：首帧与图生视频

图生视频的正确心智模型是“把一张已确定的画面交给动画师”：首帧负责外观和空间，运动提示负责如何变化。适合的首帧通常已经暗示时间瞬间、运动方向、空间纵深或环境动态。

运动提示保持短而具体，优先只写一到两个运动元素，例如：

- 缓慢推近，尘埃轻浮，灯光轻微闪烁；
- 人物向左看，短暂停顿，冷空气中呼吸可见；
- 固定中远景，缓慢向右摇，远处云层移动。

不要在同一提示中同时要求复杂表演、剧烈镜头、天气突变、服装变化和对白口型。镜头运动与主体动作需要独立可验收；生成后必须逐镜回看，不能把提示词当成已发生的事实。

片段时长只记录当前接口实测值。公开资料中的 4–8 秒或 4–10 秒是参考范围，不得直接写入本地 Provider 能力或交付承诺。项目统一采用“内容优先时长”：先测对白/内心独白的实际音频，再加动作完成、反应和恢复停留；固定秒数只能作为初始预算，不能压过完整表演。内容说不完时延长镜头，超过单镜上限则在语义停顿处拆镜。

## 阶段 3：音频要前置

音频不是最后补的装饰层。对白时长会反过来影响镜头长度和剪辑节奏，因此在视频生成前或同时生成；任何用户给出的目标秒数都不能覆盖实测内容时长：

- 为每个角色锁定一个声音配置；
- 按对白行生成并使用稳定命名，而不是整段脚本一次渲染；
- 记录停顿、语速、情绪和对白与镜头的绑定；
- 先测每条对白与内心独白的音频时长，计算“音频时长 + 动作完成/反应/恢复余量”，将其作为镜头时长；
- 若镜头仍无法容纳完整动作或独白，延长或拆镜，不得抢拍、截断、让口型漂移或把独白挤进最后几秒；
- 单独生成环境声、动作音效和音乐层，并记录来源和授权状态。

口型或复杂对白表演不可靠时，优先用静帧、背影、侧脸、切声或反应镜头承载信息，不要强行把不稳定的口型当作通过证据。

## 阶段 4：逐镜审查和选片

每个 Take 都要有最小日志：镜头号、输入资产 ID、请求/任务 ID、提示版本、生成时间、文件名、媒体哈希、时长/分辨率、状态（`APPROVED` / `REGENERATE` / `UNKNOWN`）及原因。

机器检查只能确认文件可读、编码完整、时长和尺寸可解析；导演复核还必须检查：身份、服装、道具数量、空间位置、光线、动作边界、机位、轴线、表演、对白/声音和相邻镜头连续性。

`running`、`loading`、网页上显示完成、单帧截图或旧 `video_id` 都不是交付证据。旧任务只有在合同、资产引用、时长和输出语义完全兼容且有可重建收据时才可恢复，否则保留为历史候选。

## 阶段 5：装配和全片 QC

只装配被明确选中的 Take；失败品、过期品、未知品和未复核品不能混入时间线。剪辑时：

- 以对白、音效或音乐节拍作为切点，不迷信生成片段的视觉运动弧线；
- 对不需要运动的镜头使用静帧加分层音频；
- 做统一的黑位、亮部、色温和整体色调校正；
- 生成并验证字幕轨，检查换行、阅读速度和对白同步；
- 导出后再次检查分辨率、时长、音轨、字幕、文件哈希和播放完整性。

全片交付前再做一次故事、镜头、连续性、表演、音频、剪辑和观众信息七层复核。任一层为 `REVIEW_REQUIRED` 或 `UNKNOWN`，不能写 `delivery_approved=true`。

导出后使用 `tools/validate_media_readback.py` 对照计划检查分辨率、帧数、音轨、字幕轨和时长。FFmpeg 混音收据只代表技术处理完成，默认 `human_listening=UNVERIFIED`；没有真实人耳听过并登记，音频不能变成 `VERIFIED`，也不能交付。

## 门禁和状态机

### 资产门

```text
未齐全 / 哈希失败 / 用途不明 / 桥接缺失
                    → BLOCKED
全部必填项可重建 + 引用闭合 + 连续性证据齐全
                    → READY
```

`READY` 只表示“允许进入下一阶段”，不表示已经生成成功，更不表示成片通过。每次资产包改变都必须重新计算清单和哈希；不能手工把状态改成 `READY`。

### 生成门

只有 `READY` 资产包、冻结的镜头合同、唯一 `request_hash`、引用资产清单和 Provider admission receipt 齐全，才允许提交。请求未知或中断时保留 `UNKNOWN`，先写恢复收据，不自动重复提交。

### 交付门

需要同时满足：媒体完整性、逐镜 QC、全片七层复核、字幕/音频验证、来源与权利记录、selected-only 装配和最终哈希。否则只能是 `RESEARCH_CANDIDATE` 或 `BLOCKED`。

## 失败记忆与复盘

每次失败只沉淀可复现的模式：输入资产哈希、合同版本、请求参数摘要、错误类别、媒体证据、影响范围和修复结果。一次主观意见不能改写路由；重复、哈希绑定、跨镜头复现的失败才可升级为经验规则。
